# 密钥安全自查表（第4周 · 一票否决项）

提交前逐项打钩，并在"证据"一栏写出你**怎么验证**的（老师会抽查）。全部打钩才允许 push。

| # | 自查项 | 怎么验证 | 打钩 | 我的证据 |
|---|--------|----------|------|----------|
| 1 | 代码里没有 `sk-` 开头的字符串 | 在仓库里搜 `sk-`：`git grep -n "sk-"`（应只命中 `.env.example` 里的占位符） | ☐ | |
| 2 | `.env` 不在仓库里 | `git status` 不显示 `.env`；`git ls-files -- .env` 无输出；`.gitignore` 里有 `.env` | ☐ | |
| 3 | `.env` 从未被提交过 | `git log --all --oneline -- .env` 应无输出；若有过，密钥必须立即吊销重发 | ☐ | |
| 4 | 截图/录屏里看不到完整密钥 | 只显示前 4 位；`.env` 打开时不录屏 | ☐ | |
| 5 | 密钥没发给过同学、也没粘进聊天/排错对话 | 报错文本贴给 AI 前手动打码；共享密钥课后作废 | ☐ | |

## 五项对应的讲义铁律（第7页）

- ✕ 不写进代码 → 正确做法：`os.getenv("DEEPSEEK_API_KEY")`
- ✕ 不进截图/录屏 → 正确做法：遮住，或只显示前 4 位
- ✕ 不进聊天记录 → 正确做法：报错文本里的密钥手动打码
- ✕ 不进仓库 → 正确做法：确认 `.gitignore` 含 `.env`

## 万一已经泄露了（删除文件没用！）

1. **立刻**去平台后台**吊销/删除**这把密钥，重新生成；
2. 用新密钥覆盖本机 `.env`；
3. 仓库里只删文件不够——历史里仍能搜到，需要用 `git filter-repo` 清理历史或重建仓库；
4. 检查账单，确认没有异常消耗；在课程群说明情况。

> 公网仓库上爬密钥的机器人是分钟级的：你 push 上去，几分钟内就可能被刷。**推之前先跑一遍这张表。**
