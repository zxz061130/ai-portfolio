# 作业 3：W8「学科智能问答助手 v1.0」项目预习

第 8 周要把这周的 `rag_qa.py` 和上周的 `llm.py` 组装成一个能用的助手。先把目录和分层想清楚，
再动手写——不然写到一半会发现「提示词在两处各有一份，改一处忘一处」。

## 一、目标（v1.0 的边界）

给中文教师用的一问一答助手，只回答与学科资料相关的问题：

1. 能答：资料（`data/` 三个文件 + 以后加进来的讲义、词表）里的内容，答案带出处；
2. 不能答：资料里没有的，明确说「资料中未提及」，不猜；
3. 能追问：同一个会话里记住上下文（「那五级呢？」）；
4. 断网可用：Ollama 挂着也能跑（本地模型 + 离线哈希嵌入兜底）。

v1.0 **不做**：多用户、账号、上传文件、网页抓取、语音。这些留给后面的周。

## 二、目录结构（先定形状）

```text
week08_助手/
├── app.py                 # 入口：命令行（--ask / --chat）；以后接 Streamlit 也只换这一层
├── assistant.py           # 会话编排：要不要检索、拼提示词、记历史、写日志
├── retrieval.py           # 检索层：建库 + 混合检索 + 出处（从 week07 抽出来）
├── generation.py          # 生成层：prefer 路由 + 双向回退（包装 week06 的 llm.LLM）
├── prompts.py             # 所有提示词模板集中在这，别散在业务代码里
├── config.py              # 参数集中：k、chunk、模型名、阈值，全部可从 .env 覆盖
├── logs/
│   └── sessions-YYYYMMDD.jsonl   # 每次问答一行：问题/命中/答案/引擎/耗时
└── README_windows_bash.md
```

复用而不重写（这是这次预习最重要的判断）：

| 已有 | 复用方式 |
|---|---|
| `weekpath.py` | 路径与 `.env` 继续用它，不另造一套 |
| `week06_双引擎/llm.py` | `generation.py` 里 `from llm import LLM`，prefer 切换与双向回退不重写 |
| `week07_RAG/rag_qa.py` | `split_documents` / `hybrid_search` / `format_context` / `verify_citations` / `check_numbers` 直接搬进 `retrieval.py`；`build_prompt` 搬进 `prompts.py` |
| `HashEmbeddings` | 作为「Ollama 不可用」的兜底，不删 |

**依赖方向必须单向**：`app → assistant → retrieval / generation`。
`retrieval.py` 不许 import `llm`，`generation.py` 不许 import 检索——两者只在 `assistant.py` 里相遇。
不然下周想换向量库或换模型，会牵一发动全身。

## 三、要补齐的功能（按优先级）

| # | 功能 | 怎么做 | 验收 |
|---|---|---|---|
| 1 | **会话状态** | `assistant.Session` 持 `history`，`/clear` 清空；追问时检索词拼上一轮问题（W7 已验证） | 连问「四级词汇量」「那五级呢」，第二问检索词含「四级」 |
| 2 | **路由：这问题要不要查资料** | 先用关键词/疑问类型判一下（「多少钱、几个人、第几级、多少词」这类必须查）；不需要就直连 `llm.ask`，并在输出里标「未检索」 | 问「你好」不触发检索；问「三级语法点」触发 |
| 3 | **拒答阈值** | 检索相似度低于阈值（先在 W7 的 `retrieval` 里记录分数分布再定）直接回「资料中未提及」，**不把烂上下文塞给模型** | 问「报名费多少」→ 明确拒答，不编 |
| 4 | **出处与校验** | 答案带 `（见《文件》第N段）`；`verify_citations` + `check_numbers` 在输出里显示「✓ 数字可核 / ✗ 查无此数」 | 每答必带出处；编造数字会被标出来 |
| 5 | **日志** | 每次问答写一行 JSONL：时间、问题、检索词、命中段、答案、引擎、耗时、校验结果 | 能回放一整节课的问答，供 W9 做评测 |
| 6 | **参数外置** | `k`、`chunk_size`、模型名、`prefer`、阈值都进 `.env`，`config.py` 统一读 | 不改代码换模型（0.5b ↔ 4b ↔ 云端） |
| 7 | **失败降级** | 本地挂 → 云端（W6 已有）；云端无 key → 本地；都挂 → 明确报错并给处理命令 | 关掉 Ollama 仍能答（走云端） |
| 8 | **原文可查** | 把 W7 的 `--show-context` 产品化：答完可输入 `?2` 看第 2 段的原文 | 老师能当场核对答案 |

## 四、已知风险（从 W7 带过来的）

1. **0.5b 读表格会错行**：Q1/Q5 都拿到了正确段落却读反「新增/累计」。W8 要么默认小模型只做演示、
   实际问答走云端或 4b，要么在检索层把表格转成更口语的句子（W7 已经做了一半）。
2. **数字校验有盲区**：只能证明「数字在资料里出现过」，证明不了「数字属于这一级」。别把它当正确性
   保证，当「编造报警器」用。
3. **提示词分叉**：`prompts.py` 一旦被绕过（比如某个脚本自己拼 prompt），出处格式就会不一致。
   规矩：所有提示词只从 `prompts.py` 出。
4. **库的版本**：`chroma_db` 不入库，但元信息（`w7_meta.json` 那套）要跟着代码走，
   否则换机器后「明明重建了还是旧结果」。
