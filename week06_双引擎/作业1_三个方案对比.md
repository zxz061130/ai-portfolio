## 方案 A：多轮对话（messages 记忆）

### 要改哪三处

| 位置 | 改动 |
|---|---|
| `LocalEngine` | 加 `ask_messages(messages, …)`；原 `ask(prompt)` 改成调它（不破坏现有调用） |
| `APIEngine` | 同样加 `ask_messages(messages, …)` |
| `LLM` | 加 `self.history`、`chat()`、`clear()`；`last` 多记一个 `turns` |

### 代码（可直接替换对应片段）

```python
class LocalEngine:
    def ask(self, prompt, temperature=0.7, max_tokens=800):
        return self.ask_messages([{"role": "user", "content": prompt}], temperature, max_tokens)

    def ask_messages(self, messages, temperature=0.7, max_tokens=800):
        import requests
        session = requests.Session()
        session.trust_env = False
        resp = session.post(
            f"http://{self.host}/api/chat",
            json={"model": self.model, "messages": messages,
                  "options": {"temperature": temperature, "num_predict": max_tokens},
                  "stream": False},
            timeout=self.timeout,
        )
        resp.raise_for_status()
        data = resp.json()
        if "error" in data:
            raise LLMError(f"本地服务返回错误：{data['error']}")
        return (data.get("message") or {}).get("content", "").strip()
```

```python
class APIEngine:
    def ask(self, prompt, temperature=0.7, max_tokens=800):
        return self.ask_messages([{"role": "user", "content": prompt}], temperature, max_tokens)

    def ask_messages(self, messages, temperature=0.7, max_tokens=800):
        client = self._ensure_client()
        resp = client.chat.completions.create(
            model=self.model, messages=messages,
            temperature=temperature, max_tokens=max_tokens)
        return (resp.choices[0].message.content or "").strip()
```

```python
class LLM:
    def __init__(self, local_model=None, keep_turns=8):
        self.local = LocalEngine(local_model)
        self.api = APIEngine()
        self.history = []          # [{"role": "user"/"assistant", "content": str}]
        self.keep_turns = keep_turns   # 只保留最近 N 轮，防止上下文无限膨胀
        self.last = {}

    def chat(self, prompt, prefer="local", **kw):
        """多轮：把历史一起发过去，问完把回答也存回历史。"""
        self.history.append({"role": "user", "content": prompt})
        payload = self.history[-2 * self.keep_turns:]      # 裁剪：最近 N 轮
        answer = self._ask_messages(payload, prefer, **kw)
        self.history.append({"role": "assistant", "content": answer})
        self.last["turns"] = len(self.history) // 2
        return answer

    def clear(self):
        self.history.clear()
```

`_ask_messages(messages, prefer, **kw)` 就是把现有 `LLM.ask` 的选路+双向回退逻辑复制一份，把 `first.ask(prompt)` 换成 `first.ask_messages(messages)`。**回退逻辑一行都不用改**——这是封装得值的地方。

### 优点
- **W8「助手 v1.0」直接复用**，不用到时再重构一次；W7 RAG 做单轮也不受影响（`ask()` 还在）。
- 能写进反思的素材最多：上下文长度、裁剪策略、token 增长、什么时候必须开新会话。
- 代码增量适中，且能用手边的资源验证（本地模型就能测「记不记得上一句」）。

### 代价与坑
- **上下文越长越贵**（云端按输入 token 计费，第 10 轮的 prompt 含前 9 轮），必须裁剪，否则越问越慢越贵。
- 裁剪方式有讲究：直接 `[:N]` 可能把 system 提示切掉；教学场景建议「system 常驻 + 最近 N 轮」。
- 两个引擎的 `messages` 结构要一致（`role`/`content` 字段名相同，OpenAI 与 Ollama 恰好一致）。
- 状态在对象里：同一个 `LLM()` 实例才共享记忆；CLI 里要循环调用同一实例，不能每轮 new 一个。

### 注释里可以这么写理由
> 选多轮：本周之后 W8 要做对话式助手，记忆必然要落地；现在把 `messages` 的组装点收进 `LLM`，避免在助手层再散落一套。同时用 `keep_turns` 限制历史长度，防止第 N 轮 token 暴涨。

## 方案 B：失败重试（最多 2 次再回退）

### 代码

```python
import time

# 哪些错误值得重试：网络抖动、超时、服务端 5xx。
# 401/402/404 重试一百次也没用，只会浪费时间还可能重复计费。
def _transient(exc: Exception) -> bool:
    text = f"{type(exc).__name__} {exc}".lower()
    if any(k in text for k in ("401", "402", "authentication", "invalid api key",
                               "not found", "insufficient", "balance")):
        return False
    return any(k in text for k in ("timeout", "timed out", "connection", "refused",
                                   "429", "rate limit", "500", "502", "503", "504"))

class LLM:
    def _retry(self, fn, attempts=2, base_delay=1.0):
        last = None
        for i in range(attempts + 1):
            try:
                return fn()
            except Exception as exc:       # noqa: BLE001
                last = exc
                if i >= attempts or not _transient(exc):
                    raise
                time.sleep(base_delay * (i + 1))   # 1s、2s 递增，别做忙等待
        raise last

    def ask(self, prompt, prefer="local", **kw):
        ...
        try:
            answer = self._retry(lambda: first.ask(prompt, **kw))
        except Exception as exc:
            print(f"[首选引擎失败，自动切换] {first.name} → {second.name}：{exc}")
            answer = self._retry(lambda: second.ask(prompt, **kw))   # 回退这一侧也重试
        ...
```

### 优点
- 改动最小（约 25 行），逻辑独立，和现有回退**正交叠加**：先在同一引擎内重试，再换引擎。
- 教学价值明确：**「能重试的错误」与「重试也没用的错误」必须分开**——这条判断比代码本身值钱。

### 代价与坑
- **重复计费**：一次请求 500 但服务端其实已生成 → 重试等于再付一次钱。
- 重试会拖长总时长，`timeout` 要按「次数 × 单次」预算，否则课堂演示卡住。
- 如果 `_transient` 判定写宽了（比如把 401 也放进去），会把「密钥错了」拖成 3 次无谓等待，掩盖真正的错误。
- 与回退叠加后，"成功"可能是第三次尝试才成功——测试记录里要写清走了几次，否则看起来像正常调用。

### 注释里可以这么写理由
> 选重试：课堂网络不稳，把「抖动」和「配置错」分开处理比单纯换引擎更实用；用指数退避 + 只对网络类错误重试，避免对 401 做无意义重试。

def _price():
    try:
        return (float(os.getenv("PRICE_INPUT_PER_M", "") or "nan"),
                float(os.getenv("PRICE_OUTPUT_PER_M", "") or "nan"))
    except ValueError:
        return (None, None)

### 优点
- 与 W4「算清楚一次提问花多少钱」的知识点直接接上，**跨周闭环**，反思里好写。
- 改完每次调用都自动留痕，W7 RAG 批量跑时立刻知道成本量级。
- 改动集中在「记录 + 打印」，不碰选路逻辑，风险最低。

### 代价与坑
- 本地引擎没有 token 单价（只有速度），要么打印 tok/s、要么标「本地不计费」，别硬套云端公式。
- 单价要你自己去平台价目页查并填 `.env`；不填就只能显示 token 数。
- 容易写成「为了打印而打印」——真正有价值的是**比较**：同一问题本地 vs 云端各花多少、差几倍。

### 注释里可以这么写理由
> 选费用：本周刚讲完双引擎，最该量化的是「两边代价差多少」；把 usage/单价抽成一行日志，W7 批量跑 RAG 时能立刻判断成本量级是否符合预期。

## 三个方案放在一起比

| 维度 | A 多轮对话 | B 失败重试 | C 耗时费用 |
|---|---|---|---|
| 改动量 | 中（两个引擎各加一个方法 + LLM 加 40 行） | **小**（约 25 行） | 小-中（引擎各加 5 行 + 打印 20 行） |
| 实现难度 | 中（历史裁剪要想清楚） | 低-中（错误分类是关键） | **低** |
| 对 W7–W16 的作用 | **高**（W8 助手直接复用） | 中（到处都需要，但各周可以各写） | 中-高（W7 批量、W15 上线都要算账） |
| 翻车风险 | 中（上下文膨胀、每轮 new 实例导致"失忆"） | 中（重复计费、误重试 401） | **低** |
| 反思素材 | 最丰富 | 中等（重在判断力） | 好写（有数字） |
| 讲义评档 | 优秀档要的"判断依据"，A 最容易讲出深度 | 达标-良好 | 良好 |

## 我的建议

**首选 A（多轮对话）。** 三个理由：

1. 你后面 W8 的「助手 v1.0」必然要记忆，现在做等于把返工提前省掉；
2. 它逼你想清楚「历史裁剪 + token 成本」，这正好和讲义「优秀档：能说明隐私任务走本地、复杂任务走云端」的判断力挂钩——多轮对话是唯一能演示「上下文一长，本地小模型会明显退化」的方案，你可以在测试记录里写实测对比；
3. 代码增量适中，不算作弊，也不是复制粘贴能糊过去的。

**如果你时间紧**：选 C（半天能改完并验证），把 A 留到 W8 当预习。

**不建议单选 B**：它和已有的双向回退在概念上重叠（都是"出错了怎么办"），单独交会显得薄；除非你把「哪些错该重试」的判定表写得很细。

**两个都想要**：A 为主体、C 作为 20 行附加最自然（多轮必然带来 token 增长，顺手把用量打出来）；B 等 W9 工具调用再补更合适。
